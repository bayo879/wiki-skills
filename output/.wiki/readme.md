# llm-wiki 首次接入指南

这份目录可独立分发。包含本文件的 `.wiki/` 的父目录就是目标工作区根（压缩包解压后默认叫 `output`，可改名）；资料放在此根下，知识库状态留在 `.wiki/`。这是空工具包的安装，不是已有知识库的跨机同步。

## 给尚未安装 llm-wiki 的 agent

1. 向用户确认要使用的工作区根，取得绝对路径。不要把当前终端目录或安装后的技能目录当成知识库根。路径含空格时完整引用。
2. 检查根下 `.wiki/cli/llm-wiki`（Windows 为 `llm-wiki.exe`），先运行它的 `--version`。必须使用与当前操作系统、架构匹配的 Release 包；无法执行就停止并报告，不回退到 PATH 旧版。无需 Rust。
3. 安装技能：把本工作区 `.wiki/skills/llm-wiki/` 与 `.wiki/skills/llm-wiki-session/` 复制或注册到当前 agent 支持的技能根。先确认该 agent 的实际加载规则，不假定品牌或目录。记住工作区根与包内 CLI 的绝对路径，技能被复制后仍调用这一份。
4. 若 PATH 已有其他版本的 `llm-wiki`，覆盖它的命令入口，使其指向本工作区包内 CLI；不要继续选择旧版。先枚举解析到的入口，核实将覆盖的精确绝对路径；不能覆盖目录或符号链接指向的无关目标。Unix 使用指向包内 CLI 的符号链接（替换链接本身，不沿链接覆盖旧目标）；Windows 使用启动器，调用包内 exe 并原样转发参数和退出码，处理同名 exe 优先级。权限不足或超出沙箱时请求授权，不偷偷跳过。不要把二进制复制到 PATH：脱离 `.wiki/cli/` 后它会失去包根定位。PATH 不存在命令时可直接使用包内绝对路径，不要求全局安装。
5. 用包内 CLI 执行 `doctor`。只有安装文件的全新包会自动创建配置、页面目录与账本；不用先跑修复。若已有知识库但缺配置或页面，则按诊断处理，不能当新包覆盖。健康检查失败要报告具体项；`doctor --fix` 仅用于可修机械缺陷。
6. 加载 `llm-wiki` 技能，阅读其 `init.md`：写入工作区记忆，并询问是否安排「wiki自动摄入」（默认每天 01:00，由用户确认时区与周期）；没有明确同意，不创建定时任务。调度中固定工作区根和包内 CLI，不能依赖调度器的当前目录。

## 使用与校验

假设用户确认的根是 `/path/to/output`，在任何目录均可执行：

```sh
"/path/to/output/.wiki/cli/llm-wiki" --version
"/path/to/output/.wiki/cli/llm-wiki" doctor
"/path/to/output/.wiki/cli/llm-wiki" query "要查的问题"
```

源文件与载荷文件的相对路径都以包根为准。CLI 不自动扫描调用者所在的其他目录。直接使用包内绝对路径最可靠；覆盖 PATH 入口后，重新打开 shell 或刷新命令缓存，并核对实际入口与 `--version`。多工作区时分别用各自包内 CLI 的绝对路径，不以全局入口猜测目标。移动包后重新安装 PATH 入口、更新记忆与定时任务中的路径。

工具只向 `.wiki/` 写入，不删除源文件。页面合并没有内置回退；自行安排独立备份。不要把运行后已有数据的目录当作空工具包再次分发。
