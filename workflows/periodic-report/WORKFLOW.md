# 周期工作报告

## 适用

用户要求整理个人或团队周报、月报、季报、年报或周期工作总结。这里的年报指年度工作报告，
不是上市公司法定年报；需求有歧义时先确认。资料入口是已生成的 wiki，
不是重新扫描文件或自动连接邮件、聊天、项目系统。工作流本身不提供定时调度或自动发送。

## 边界

在实际知识库工作区根目录执行命令，使用技能脚本实际路径，遵守工作区边界。
直接查询，不以前置 `check`、`init` 或确认账本存在作为查询门槛；`query` 打开账本时可能自动
补齐目录、配置和表，补齐情况见返回的 `data.repaired`，因此不承诺 CLI 查询完全无写入。
这不等于摄入资料：不为生成报告主动执行 `ingest`、`next`、`submit`、`sync` 或修改知识页。
没有已有知识或没有足够记录时，说明需要另行授权补充资料，交付缺口或有限草稿，不能编造。

## 步骤

1. agent: **确定报告范围**：整理已知的周报/月报/季报/年报、个人或团队、项目范围、读者、篇幅及起止日期。 将“本周”“上月”“本季度”“去年”等转换为用户时区下的明确日期区间（含首尾日期），展示采用的区间。 周报沿用约定的周起始日；月报、季报、年报默认自然月、自然季度、自然年。 不把当前日期当成记录日期。周期未结束时注明“截至某日”，区分计划周期与实际数据截止日， 不将阶段数据写成整个季度或全年的最终结果。
2. human: **条件确认范围**：仅当报告类型或范围有歧义、必要信息缺失、用户时区不明，或周起始日不明确 且影响归属时，停下来询问用户；采用财年、财务季度或其他业务周期时也须确认其定义。 已有明确约定则沿用，不重复询问，不替用户决定有歧义的范围。
3. tool: **多轮检索 wiki**：执行 `python3 <skill>/scripts/wiki.py query "<关键词>" --json`， 按目标、职责板块、项目名、业务别名、工作事项、里程碑、成果、问题和计划分别查询。 先用 2–4 组关键词，再据命中补查相关项目；这不是长周期报告的查询次数上限。 不能只搜索报告类型或日期字符串。既有报告与话题可作线索，相关 `data.topics` 项按其实际返回的 `path` 用文件读取工具阅读；事实回到对应知识页和 raw，不循环引用生成稿自证。 季报按月补查，年报按季度补查，必要时细化到月份。 建立“项目 × 时间段”覆盖清单，区分有已核实记录、记录不足、日期不明，不能只总结最近资料。
4. tool: **阅读页面与原文**：用命中项的 `id` 执行 `python3 <skill>/scripts/wiki.py query --page "<page-id>" --json`，阅读返回的 `data.body` 与 `data.page`。 原文按该返回的 `data.sources[].raw` 真实路径，用文件读取工具打开工作区内的观看区副本； 来源 key 取同项的 `key`。不自行拼接原文文件名，不把检索结果的 `sources` 当作含路径的对象。 路径为空或文件不可读时标明原文缺失，不伪造路径，也不主动领任务取原文。 长原文按文件读取工具实际提供的行号或分页能力续读，不假设查询返回分页字段。
5. agent: **抽取工作记录**：建立工作记录表，字段至少为：工作事项、项目、事件日期、状态、 成果/指标、本期新增或累计、问题/风险、下一步、页面 id、raw key（来源 key）。 缺失字段标待确认。资料中的“上周”等相对时间应依据该资料的记录日期解析，不能按今天解析。
6. verify: **核验日期与状态**：页面 `updated` 是维护时间，不是事件日期。根据正文或 raw 判断周期归属， 无法判断的另列待确认。核对关键数字、日期、责任主体、完成状态；stale 页面经 raw 核验后 才能使用，不能无提示视为最新。页面与 raw 冲突以 raw 为准并说明，多份 raw 冲突保留双方口径。 回顾历史周期时仅采用截至期末的可证实状态，不能把后来完成的工作倒算到该周期。
7. agent: **去重并汇总**：同一项目、事项或交付物跨页面、跨周、跨月及跨季度合并，保留来源映射。
   - 区分已完成、进行中、受阻、待确认；计划不能升级为已完成。
   - 同一成果在多份报告中出现只计一次，阶段成果与最终成果说明关系，避免重复累计。
   - 区分本期新增与累计成果。可累加的期间数据，确认范围、单位、统计口径一致且时间不重叠才求和。
   - 时点数据（如期末在岗人数、项目余额）取对应期末值，不能按月相加；无期末数据则标缺失。
   - 比例与均值需有分子分母或权重才汇总，不能直接相加或无权重平均月度完成率。
   - 同比、环比、目标达成率须有可比数据及目标依据；计算注明公式、口径与来源，缺失则不编造。
   - 年内目标或统计口径调整时，标明调整时间与影响，不混用新旧口径。
   - 连续跟进同一事项不是多项独立成果；月报不拼接周报，季报不拼接月报，年报不拼接季报。
8. agent: **整理下期计划**：优先采用已有明确安排。根据问题提出的新行动须标“建议”， 没有依据不得编造责任人、截止日期、承诺或目标数值；下一年度建议目标不能冒充已批准计划。
9. agent: **起草报告**：按下面模板输出。周报重具体推进与阻碍；月报重阶段成果、项目进展与指标； 季报按目标和重点项目归纳，重季度目标、里程碑、跨月趋势与资源问题； 年报按年度目标和成果主题归纳，重核心成果、长期变化、复盘与来年规划。 无目标或历史可比数据时不能宣称达标、增长或改善，标明缺失口径。
10. tool: **按需应用个人风格（仅用户要求时）**：显式执行 `python3 <skill>/scripts/wiki.py workflow search "个人风格" --json`，命中相关工作流后执行 `python3 <skill>/scripts/wiki.py workflow load "personal-style-writing" --json`，复用其风格检索与表达规则。 不改变已经核验的事实表，不递归调用本工作流，不声称加载了不存在的工作流。 未命中或没有风格依据时：一般风格偏好可说明局限并提供中性草稿；用户明确要求精准模仿时， 先暂停询问是否补充样稿或接受中性版本，未经确认不替换交付目标。
11. verify: **复核与交付**：对照记录表检查事件归属、去重、状态、数字及来源，另列覆盖范围、 来源和待确认项。说明这是基于已检索记录的草稿，不宣称完整覆盖全部工作。
12. human: **条件确认保存位置**：仅当用户要求保存但未明确合规的工作区内位置，或目标已有旧稿 且是否更新不明确时，停下来确认保存位置或更新授权；默认只在回复中交付，不自动保存、发送或摄入。 已有明确保存位置和授权则直接按授权执行，不能跨工作区保存。
13. tool: **保存（仅用户明确要求且位置已确认时）**：用文件写入工具保存草稿，遵守技能的工作区与 草稿存放边界；文件名包含报告类型和周期，不覆盖旧稿，除非明确要求更新。报告实际路径， 并说明未执行摄入、知识页回写或发送。不编辑观看区的知识页或原文副本。

## 检索命令示例

```bash
python3 <skill>/scripts/wiki.py query "<项目名>" --json
python3 <skill>/scripts/wiki.py query "<里程碑或工作事项>" --json
python3 <skill>/scripts/wiki.py query "<问题或计划关键词>" --json
python3 <skill>/scripts/wiki.py query --page "<page-id>" --json
```

页面正文取 `query --page` 的 `data.body`，来源 key 与原文路径分别取 `data.sources[].key`、
`data.sources[].raw`，原文通过文件读取工具读取实际返回的路径。普通关键词查询的
`data.results[].sources` 是来源 key 列表，不提供这些原文路径。

当前检索是关键词匹配，不是结构化的按事件日期查询。知识页仅保留最新状态、没有历史日期时，
不能还原对应历史周期的工作。命中是排序子集，不是覆盖证明；无命中不等于没开展工作。
季报、年报先完成各时间段覆盖检查，再以连续一轮无新增有效记录或材料已足够作为停止条件；
仍未覆盖的时间段必须列入缺口。用户要求穷尽而检索无法证明覆盖时，明确说明限制，不静默缩小范围。

## 周报模板

```markdown
# 工作周报（起始日期—结束日期）
## 本周概览
## 已完成工作与成果
## 进行中工作
## 问题、风险与需协调事项
## 下周计划
```

## 月报模板

```markdown
# 工作月报（起始日期—结束日期）
## 本月概览与目标达成
## 重点项目进展与阶段成果
## 指标汇总（区分本期与累计）
## 问题、风险与复盘
## 下月重点与资源需求
```

## 季报模板

```markdown
# 工作季报（起始日期—结束日期）
## 季度概览与目标达成
## 重点项目与关键里程碑
## 指标汇总与跨月变化
## 问题、风险与资源需求
## 季度复盘
## 下季度重点计划
```

## 年报模板

```markdown
# 年度工作报告（起始日期—结束日期）
## 年度概览与目标达成
## 核心成果与重点项目
## 年度指标与变化分析
## 主要问题与经验复盘
## 下一年度目标与重点计划
```

周期未结束时在报告标题或开头注明“截至 YYYY-MM-DD”。
无可靠信息的章节写“暂无已核实记录”或“待补充”，不写成“无问题”或“无工作”。用户有固定模板则优先使用。
正文之外附：
- **来源说明**：关键事项对应页面 id 和 raw key，必要时标明核验状态。
- **覆盖与缺口**：检索涉及哪些项目、哪些时间段或事项尚缺记录。
- **待确认事项**：冲突、日期不明、状态未核实、待补指标；无则写“无”。

## 保存与完成标准

默认直接交付草稿，不自动发送、保存或摄入。用户要求保存时，按步骤中的条件确认和写入规则办理，
文件名包含报告类型和周期，不覆盖旧稿，除非明确要求更新。报告路径并说明未执行摄入、回写或发送。
不输出凭据或不必要的个人联系方式。

完成前确认：已检索 wiki 并读页面；关键记录可追溯；事件日期不混同页面更新时间；
本期与累计分开、跨周期事项去重；期间数据与时点数据分别处理，指标口径一致；
季报、年报已检查各时间段覆盖，未结束周期已标明截止日；
计划和建议未伪装成成果或已批准目标；stale 与冲突得到核验或明确标注；
未因检索无命中宣称没有工作，未宣称无法证明的完整覆盖。
