# 整理标准：什么值得成为一页

引擎保证“做得对”，这份文档保证“写得对”。没有语义判断的摄入只是把 PDF 换成
Markdown，不构成知识库。

## 页面边界

一页 = 一个可独立检索、可独立引用的主题。用三个问题判断：

1. **别人会单独搜它吗？** 会，就值得独立成页（“反诈模型备案要求”会被搜，“通知第一段”
   不会）。
2. **它需要自己的出处组合吗？** 一页可以引用多个来源；如果某部分事实来自另一份文件且
   结论不同，拆页比混写更清楚。
3. **更新时它会整体变化吗？** 年度通报、专项方案这类按版本整体替换的内容适合一页；
   长期概念适合一页并持续追加。

反面模式：

- 按文档结构拆页（“一、二、三”各一页）→ 检索碎片化。
- 一份文件一页、只写摘要 → 没有独立主题，无法复用。
- 把多个不相关主题塞进“工作笔记” → 摘要无法概括，检索命中噪声大。

## 标题与摘要

- 标题：名词短语，包含区分性限定（时间、范围、主体）。例：
  `火灾隐患排查整治专项工作（2025-12 至 2026-01）` 优于 `消防通报`。
- summary：一句完整的话，能脱离正文阅读；写结论与适用对象，不写“本文介绍了……”。
- 类型：`concept` 要求/概念；`entity` 组织/系统/人物；`process` 流程/专项工作；`note` 杂项。
  拿不准用 `concept`，不要为类型纠结。章节由任务模板按类型给出。
- 版式：章节由模板固定，节内按类型的固定组合写；每种类型的正文模板见 `../templates/`
  下的同名文件（concept、entity、process、note）。

## 证据标准

每个数字、文号、日期、责任主体都要能回到对应的 raw。

- `evidence[].quote` 必须从 raw 逐字复制（比较时忽略空白），长度不超过一两个短句。
- 正文末尾的“证据”由引擎按 `evidence` 自动渲染；`boundaries` 写入页面元数据，不要在正文重复。
- `boundaries.covered` 写这一页回答什么问题，`boundaries.not_covered` 写明确不覆盖什么。
- 引用原文用短引号，不整段复制；长引用放 raw，页面只留结论。
- 推断要标注：“据此推断”“口径未在原文说明”。不要把推断写成原文事实。
- 个人手机号、邮箱等联系方式不写入页面；写“联系人见原文”。
- 数字冲突时并列两个口径与各自出处，不要自行选一个。

## 新建、合并还是跳过

| 情况 | 动作 |
| --- | --- |
| 新主题，现有页面不覆盖 | `new`，给页面 id、标题、类型 |
| 现有页面已覆盖同一主题，只是补充/修订 | `merge`，读完旧页后提交新修订 |
| 同主题页面已排队、但还没写入 | `merge` 到 `pending_pages` 里的 id，来源会并入该页面任务 |
| 同一事件的新版本通报（如第 2 期） | 并入同一页，标题与 summary 更新为最新口径，正文保留历史对比 |
| 纯附件、空白页、重复件、与知识库主题无关 | `skip`，`reason` 写清为什么不要 |
| 内容看不懂/解析乱码 | 不要建页；向用户说明，等解析修好后再摄入 |

**合并优先于新建。** 同一主题出现第二页是最常见的质量退化；建页前先查已有页面标题。

## 链接

- 关联由 route 决定：在 decision 的 `links` 里写目标页 id，page 模板会带过来。正文里
  不要写 `[[page-id]]` 或 `## 关联`，两者都不产生图边。
- 只指向提交时已存在的页；同一次 route 拆出的兄弟页，等被链页先提交再交本页，顺序错会
  报 `E_LINK_UNRESOLVED`，重新领取后按顺序重试。
- 更新页的 `links` 只能增：模板带出已有链接，提交时取并集；没有删链入口。
- 观看区在页末用一个 `## 关联` 段混排出链与入链，反向链接自动出现，不需要手写。
- 链接是“读者下一步可能想看”，不是关键词堆砌；一页 2–5 个出链足够。

## 完成标准（自查）

- [ ] 每个来源都有归属决定：新建、并入或跳过，理由写清；一份来源可拆成多条决定。
- [ ] 每个页面任务都已提交；被拒后重新 `next` 领取（通常同一 id），再按 `error.next` 修正后重交。
- [ ] 每页 `sources` 非空，`evidence` 的引文能在对应 raw 里逐字找到。
- [ ] `boundaries.covered` 与 `boundaries.not_covered` 都写了，不是空泛的“全面覆盖”。
- [ ] 数字、日期、文号与 raw 一致（抽查至少 3 处）。
- [ ] 没有两个页面在讲同一主题。
- [ ] 回答用户问题时，能同时给出页面 id 与原始文件 key。

## 示例（真实语料）

同一批 4 份公文，正确的页面粒度是 5 页（其中一份讲话拆成两页），而不是 4 段摘要：

| 来源 | 页面 | 理由 |
| --- | --- | --- |
| 反诈模型通知 | `anti-fraud-model-operations` | 一组可独立检索的运营要求 |
| 火灾隐患通报 | `fire-hazard-inspection-2026` | 带时间范围与统计口径的专项工作 |
| 云网安全讲话（主题日活动） | `cloud-network-safety-day` | 活动本身：启动会、活动主题与三项人员能力要求 |
| 云网安全讲话（“双零”行动） | `dual-zero-action` | 独立行动：变更操作零失误、云网安全零事故 |
| 天翼云维护方案 | `tianyi-cloud-one-city-one-pool` | 长期方案，按结构建页 |

同一份讲话拆成两页，是因为“主题日活动”和“双零”行动会被分别检索；一份文件只建一页，
就会把两个主题压成一段摘要。后提交的一页在 decision 的 `links` 里指向先提交的一页，
表达“同属安全生产条线”；两页各自保留独立出处。
