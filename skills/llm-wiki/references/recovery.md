# 故障与恢复

原则：**raw 与页面是资产，数据库是账本。** 账本坏了可以重建，页面被覆盖才需要备份。

## 一、来源解析失败

`ingest` 的 `unsupported` 会给出后缀与提示。按顺序处理：

1. **PDF 无文本层**（扫描件）：`pdftotext` 返回空。此时不要建页；让用户提供 OCR 文本，
   或安装 OCR 后把结果另存为 `.md` 再摄入。
2. **PDF 有文本但乱序**：用 `pdftotext -layout` 已默认开启；仍乱序时检查 raw 前几十行，
   必要时 `--force` 重跑；不要基于乱码写页。
3. **DOCX 解析为空**：确认是 `.docx` 而非改扩展名的 `.doc`；老 `.doc` 先用办公套件另存。
4. **编码问题**：文本按 UTF-8 → GB18030 → Latin-1 降级解码；仍异常时用 `read` 抽查 raw，
   不要凭印象补内容。
5. **单文件超限**：默认 50 MB。调大 `.wiki/wiki.json` 的 `ingest.max_source_bytes`，或把
   大文件移出知识库根目录。

解析失败不会阻塞其他文件；`ingest` 退出码为 1 只表示“有需要处理的项目”。

## 二、来源消失或内容变化

- 源文件被删除/改名：下次 `ingest` 把来源标 `missing`，引用页标 `stale`，正文保留。此时
  页面仍可读，但回答时要说明“来源已不在原位”。
- 源文件恢复且摘要不变：自动回到 `done` / `stable`，无需重写页面。
- 源文件内容改变：来源回到 `pending`，raw 被覆盖，引用页标 `stale`。此时**必须**重读 raw，
  修订页面并重新 `page put`（默认写回 `stable`）；否则 `settle` 会以“引用页仍为 stale”
  阻断。旧结论若已失效，在正文中改掉，不要只在末尾追加“补充”。
- 页面长期 `stale`：`doctor` 会提示。要么补回来源，要么把页面改成不依赖该来源的表述，
  要么删除页面（`page delete --yes`，先备份）。

## 三、页面冲突与误操作

- **误覆盖页面**：`page put` 是整页替换。若没有版本控制，先在 `.wiki/pages/` 找同 id 的
  旧文件（已被覆盖则无法恢复）。建议把 `.wiki/pages/` 与 `wiki.json` 纳入 Git，忽略
  `raw/` 与 `wiki.db`（可重建）。
- **误删页面**：`page delete` 不可逆；只能从备份/Git 恢复。删除前先 `read "page:<id>"`
  留档。
- **链接指向不存在页面**：`doctor` 报 `L9`。改链接或补页，不要留悬空引用。
- **重复主题**：保留信息更全的一页，把另一页的独有事实并入后删除；不要两页互链假装无事。

## 四、数据库与并发

- `wiki.db` 损坏：`doctor` 报 `E_DB` 或 `L1`。不要手改 SQLite 文件。用备份恢复；没有备份
  时，删除 `wiki.db` 后重新 `ingest`，页面文件不受影响，但所有来源会重新进入 `pending`，
  需要重新 `settle`（页面引用关系仍在，settle 可直接通过）。
- 并发：SQLite 有 5 秒 busy timeout，但不要并行跑两个写命令。多个 agent 同时工作时，
  用“一个写者 + 其他只读”的约定。
- 中断：页面与 raw 都是临时文件 + 原子替换，不会出现半截文件；中断后重跑同一条命令即可。

## 五、备份与迁移

```bash
# 最小备份：页面与配置
tar czf wiki-pages-$(date +%F).tgz .wiki/pages .wiki/wiki.json

# 完整备份（含账本与 raw，可离线还原）
tar czf wiki-full-$(date +%F).tgz .wiki
```

整个根目录搬迁时连 `.wiki/` 一起复制；`sources.key` 是相对路径，根目录移动不影响引用。
只复制技能目录不会带走知识库。

## 六、什么情况下停下来问人

- 两份来源对同一事实给出互斥口径，且都像正式文件。
- 来源涉及个人隐私、合同金额、未公开人事信息，而用户没有说明可否入库。
- 需要 OCR、解密或访问知识库之外的系统。
- 页面大量 `stale` 且无法判断应以哪版为准。

停下来时说明：哪一页、哪两个来源、冲突点、可选处理方式。不要自行选一个继续。
