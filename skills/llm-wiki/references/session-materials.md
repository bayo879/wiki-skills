# 会话素材：提炼与写入

本文件是 llm-wiki 技能的会话素材标准，`SKILL.md` 只给触发条件、边界与入口；具体判断与
写入流程以本文件为准。

## 定位

从当前会话提炼可复用知识，写入当前项目根目录的 `wiki-sources/`。产物是供 wiki 后续处理的
**素材**，不是正式知识页，也不是聊天记录。写入素材不代表已摄入。

只维护本项目素材；摄入、跨来源去重和知识页维护由 wiki 内部处理。这条流程不运行 wiki
CLI，不要求工作区已有知识库，不直接修改知识页，不跨工作区写 wiki，不配置同步。用户手动
将素材目录加入 llm-wiki 客户端管理。

## 先判断归属

- 项目事实（目录、命令、配置、已实现行为）：归项目产品文档。
- 必须持续生效的规则、项目强制约束：归对应层级的指导文档；规则变更遵循用户授权，不能只存
  wiki 素材。
- 未决问题、待实现或待验收事项：归项目 issues，不包装成已有能力。
- 可跨项目复用的方法、经验、踩坑与方案分析：才进入本流程的素材。
- 临时命令、调试流水、没有复用价值的讨论：不保存。

一个会话可能包含不同归属。向用户说明分流，不把所有内容塞进素材；修改其他文档仍按该项目
指导执行。

## 提炼什么

判断标准：三个月后的 agent 能否据此更快做对类似的事？保留能改变判断的信息：问题背景、
结论、理由、触发条件、适用范围和未确认事项。不凑条数，不为一次会话强行建档。

区分实测事实、用户约束与 agent 推断；候选方案明确标为未验证，不能写成已确认结论。项目
约束只作为分析背景，不推广成普遍规则。没有可复用结论时说明不保存。

例如：项目运行环境固定为 Node 22，实测依赖 A 不兼容，推断 B 可能替代但未验证。素材应保留
A 的失败条件和选型检查方法，把 B 标为待验证候选；不能写成“所有项目必须用 Node 22”或
“B 已可替代 A”。

## 授权与内容安全

- 用户明确要求保存且主题清楚：直接执行，不重复询问同一授权。
- agent 主动发现值得保存的经验：先展示标题和一句话要点，征得同意后再写。
- 保存范围含糊或包含敏感内容：先澄清范围，必要时脱敏；不保存密码、Token、API Key 等凭据。
- 用户明确不留：不落盘。

## 写入流程

1. 确认当前项目根目录；不明确就问，不从已复制的技能位置推测，更不寻找另一个 wiki 工作区。
2. 按主题检索当前项目 `wiki-sources/`；目录不存在时，在获准保存后创建。读相关素材全文，
   判断补充已有主题还是新建。
3. 一主题一份 Markdown，以主题命名，如 `wiki-sources/runtime-dependency-selection.md`。
   一个会话可拆多个主题，多次会话可补充同一主题，不默认按日期切会话档案。
4. 素材写清：**背景、结论、理由、适用条件、未确认事项**；没有未确认事项就明说。正文应
   脱离聊天上下文也能读懂，不要求 wiki 页面 id、专用 frontmatter 或内部链接。
5. 更新已有素材前重读，保留其他有效内容；结论改变时突出当前结论，仅保留解释改判所需的
   旧判断和依据。无法确认冲突就询问，不静默覆盖；并发修改先协调。
6. 复核实际写入内容与保存范围，向用户报告提炼了什么、素材路径，并明确“未执行摄入”。
   不声称已入库。

## 边界

素材默认保留，不在写完或摄入后自动删除。是否纳入 Git 由项目决定，不擅自修改忽略规则。
不把素材当作强制指导，也不以保存素材代替维护项目文档。
