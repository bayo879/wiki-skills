# 运维：体检、同步、冲突与回退

## 体检

- `doctor` 看目录、配置、锁、暂存区；`lint` 看页面内容。两者都先跑，再动手。
- `lint` 有 error 先修。warning 是给人看的信号，不要为了清零改阈值或往正文注水。
- `lint --fix` 只修机械缺陷：缺失或过期的日期、过期索引。它不判断对错。
- 修完重跑 `lint`，确认 error 清零再报告。

## 判断层

`lint` 不判断的，要你读正文：

- 矛盾：两页对同一件事结论相反。
- 过时：源变了，页没变。
- 孤儿：页在，但没人链它、也搜不到。
- 重复：两页讲同一件事。

出一份 3 到 5 条的报告，每条给页面和一句话证据；不要顺手改。要不要动，交给用户。

## 同步

- `sync` 是无人值守的一条命令：扫描、摄取、重建索引、写审计。
- 只让一部分源进来，用 `sync --only`。
- 先读审计报告再汇报；失败时看退避状态，不要立刻重试。
- 连续失败，或暂存区持续堆积：叫人。

## 冲突与回退

- 内容冲突：停下来问用户，不要用 `submit --confirm` 硬发。
- 发布错了：`history` 看版本，`diff` 看差异，`rollback` 整版回退。
- 回退后要重新 `scan`，否则旧源会被当成新变动再来一轮。
- 不要靠删页面来「回退」；删页是另一个决定，得用户点头。

## 忽略列表

- 生成物、缓存、大二进制进 `.wiki/ignore`，用 `ignore` 命令加，不要手改文件。
- 忽略是永久的；先 `ignore check` 看一眼再决定。
- 忽略只挡后续扫描，不改变已经存在的页。

## 什么时候叫人

- 两个源给出相反结论，且都有证据。
- 需要删页、拆页或大改结构。
- 同步连续失败，或锁长时间不释放。
- 任何你判断不了、又不敢静默继续的事。

不要把「我拿不准」包装成「已完成」。宁可停一次，也不要发布一个错结论。
