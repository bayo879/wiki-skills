# llm-wiki

## 边界

- 源文件只读；作者直接写 `.wiki/pages/` 正式页面，落盘立即生效。
- 工具维护 raw、账本、索引与锁；作者维护页面正文、真实来源与更新日期。
- 没有候选发布步骤、工具内版本或回退，也不自动备份。覆盖旧页前先确认风险；需要恢复时只能使用用户已有的独立备份，不要承诺能撤销。
- CLI 锁不覆盖作者直接写页，并发作者可能互相覆盖；同一页只安排一个作者，写前重读。
- 对外命令是 `doctor`、`ingest`、`done`、`query`、`ignore`。命令参数及字段以 CLI 输出和帮助为准。

## 用与不用

- 查方案或历史结论：先 `query`，不要为了查而写页。
- 整理材料：走下面的最小序列；一页讲清一件事，不转述全文。
- 一次性代码问题或项目事实：直接读代码或维护项目文档。
- 会话中值得留的通用判断：用 `llm-wiki-session`。
- 用户没有授权写入：只检索，先展示拟写的标题与要点，等明确同意。

## 最小序列

1. `doctor` 看健康与变化；有 Fail 先修。
2. `ingest` 转换源、登记来源待办，交付正式页位置、类型、schema、raw 哈希与受影响页。中断后重跑仍能看到未完成来源；不是每个来源都必须新建页。
3. 实际读取 raw，保存所读字节对应的哈希；同时重读受影响的已有页。按 schema 直接写正式页，作者显式填写真实使用的来源与更新日期，工具不代补。
4. 自检正文、来源与链接，并用 `query` 验证直接写入的页可检索。确认本次来源已处理后，才用 `done` 携带实际读取的 raw 哈希逐源确认。
5. 漂移则保留待办，重新摄入、重读并核对已经写入的页，再确认。不要换成当前新哈希替旧阅读背书；确认只清这一来源，不发布、不验证正文、不撤销页面。

刚改过的源默认等稳定窗口；`--force` 可跳过等待并全文复核，但不能越过最大源文件体积。元数据缓存可能漏掉大小与修改时间都保持不变的改动，需要时强制复核。

## 停点与报错

- 结论冲突、需要删页或大改结构：问用户，不静默覆盖。
- `error.code` 分类，`error.message` 指下一步；有 `error.detail` 时以具体证据为准。
- 退出码 1 是执行失败或体检 Fail，来源漂移时不要确认完成；退出码 2 修用法、配置或环境；退出码 4 等占锁进程结束。
- 未初始化按 message 跑 `doctor --fix`，再按其末尾指引处理项目指令及定时任务；定时安排必须先问用户。
- 找不到命令先找项目构建产物，不绕过 CLI 手改账本。

## 写页与汇报

- 先 `query` 查重，短更新并入已有页；独立结论才新建。内容判断见 content.md。
- 结论变了保留旧判断与改判依据；来源只填实际支撑本页的证据。
- 汇报结论、写到哪、哪些来源尚未确认。页面已写但确认失败，必须明确页面仍已生效。
- 不把来源确认成功说成正文正确或可回退；不要贴整份 JSON。

## 按需阅读

- content.md：建页、证据与改写。
- ops.md：体检、漂移、覆盖风险、忽略与叫人。
