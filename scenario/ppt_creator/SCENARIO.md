# PPT 编写

## 适用

用户要拿幻灯片给人讲一件事：汇报、路演、培训、提案、复盘。核心难点在“讲什么、凭什么讲”，
排版交给 `pptx` 技能。

只想要一个文件、内容自己已经想好，不适用：直接加载 `pptx` 技能。

## 前置检查

动手前确认两件事，任一不满足就停止并说明缺什么，**不降级自己写 PPT 生成脚本**：

1. 本会话能加载 `pptx` 技能，读得到它的 `SKILL.md`，并能按它的流程执行。
2. `python3 <skill>/scripts/wiki.py check --json` 返回 `ok: true`。

## 步骤

1. **简报**：一次问清这些，不要挤成多轮追问。
   - 主题：一句话，能给标题用；
   - 听众：什么角色、关心什么、已经知道什么；
   - 场合与时长：据此估页数，3–5 分钟一页；
   - 必须包含 / 不得出现：硬要求、竞品、敏感表述；
   - 保密与脱敏：哪些内容不能进幻灯片；
   - 有没有现成模板或品牌规范。
   用户没答的给默认值，交接时标注“未提供，按默认处理”。

2. **取证**：换 2–4 组关键词 `query`（同义词、上下位词、业务别名），读命中页面；
   数字、日期、文号、责任主体要核对时 `read "raw:<key>"`。只留能支撑论点的材料。

3. **组论点**：先写一句主线——听众散场后要记住的那句话；再列 3–5 个支撑论点，每个论点
   对应 1–2 页，论点之间要有推进（现状 → 原因 → 做法 → 代价 → 下一步）。

4. **逐页大纲**：每页写标题、一句话结论、3–4 条要点、依据、图表建议。标题写成结论，
   不写“背景”“概述”这类空词；依据写页面 id 或 `raw:key`。字段见 `references/outline-template.md`。

5. **自查**：每页都有依据或已标缺口；没有超出“不覆盖”范围的结论；没有个人联系方式与凭据；
   把各页标题连起来读，能读成一段通顺的话。

6. **交接**：把“简报 + 逐页大纲”整块交给 `pptx` 技能，并说明受众、时长、页数、内容来源
   已经确定，只需要它确认输出路线、视觉风格、生成模式与配图方案。这些不要重复问用户。

7. **回填**：交付后说明实际页数、用到的依据、没用上的材料、仍缺依据的页。

## 判断点

- 某论点查不到页面：标“缺依据”，问用户是补摄入还是换论点，不编。
- 页面与 raw 冲突：以 raw 为准，写明冲突位置。
- 页数撑不住论点：减论点，不把一页塞成两页。
- 主题一次讲不完：拆成两场或留附录页，先讲最影响决策的部分。
- 涉密内容、个人联系方式、凭据：不进大纲。
- 用户只要大纲不要文件：停在步骤 5。
- 没有 `pptx` 技能：拒绝执行并说明原因，等环境补齐再继续。
- 交接时 `pptx` 技能反过来问受众或时长：直接把简报里的答案给它，不让用户重答。

## 交接格式

给 `pptx` 技能时用下面这块，别只丢一句“做个 PPT”：

```markdown
## 已定（无需再问）
- 主题：<一句话>
- 听众：<角色 + 关心点>
- 时长/页数：<15 分钟 / 约 10 页>
- 内容来源：wiki 页面与 raw，已在每页标注依据
- 必须包含：<...>
- 不得出现：<...>

## 逐页大纲
1. <标题> — <结论句>
   - <要点>（依据：page-xxx）
   ...
```

## 完成标准

- 每页都有依据，或明确标注“缺依据”；
- 简报完整，交给 `pptx` 技能时没有重复提问；
- 交付后说明依据清单与缺口，不把推断写成事实。

## 不做

- 不自己生成 `.pptx` / `.html`，不写渲染脚本，不装第三方库。
- 不改 `SKILL.md`、`query` 或引擎，不做自动注入。
- 不把大纲写进 `.wiki/`，不当知识页。
- 素材不足不编造。
