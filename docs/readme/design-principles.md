# 设计与边界：skill 与 CLI

这套工具把「判断」和「机械动作」分开：CLI 负责可重复的本地状态转换，skill 负责顺序、判断与对人的停点。下面这些原则用来回答「这个改动该落在哪一层、会不会把边界弄坏」。

## 分工

| 层 | 负责 | 不负责 |
|---|---|---|
| CLI | 状态转换、锁、账本、索引、来源待办、稳定输出与退出码 | 页面正文的语义判断、替作者写页、替用户排定时任务 |
| skill | 顺序、门禁、判断、停点、汇报、首次接入 | 复述字段表与错误码、手改 `.wiki/`、绕过 CLI 做机械动作 |

## CLI 原则

1. **单一入口，单一事实。** 账本业务写入只走 `Ledger`；引擎目录只认 `LAYOUT`；初始化只走 `open_repo` 与 `doctor`；忽略只认 `IgnoreList`。同一件事出现第二份实现，迟早会出现两个答案。
2. **输出是契约，不是日志。** 人类输出只给结果与下一步；机器输出走 `--json`。字段形状由快照锁定，改形状就改快照，不靠记忆同步文档。
3. **只给内部引用。** 命令输出用仓库相对引用，不打印绝对路径或目录树；读文件走 `read`。错误只给稳定码、可行动的原因与下一步。
4. **少交互，自动收口。** 能由规则判定的就由工具做：空仓库自动建默认库、源消失自动清引用与账本、失败源让位但不永久排除。只有结论冲突、删页、大改结构这类需要人判断的事才停下来问。
5. **默认安全边界要说清。** 页面直接落盘，没有候选发布、工具内版本、回退或自动备份；删页与删 raw 不可撤销；并发作者可能互相覆盖。技能必须提前说明这些代价，不能承诺工具能撤销。
6. **触发话术属于调用方。** `wiki自动摄入` 是用户或调度器的 prompt，映射到 `llm-wiki ingest --auto`：CLI 只跑默认一轮，读 raw、拆解、逐叶提交并用 `task done` 推进仍由 skill 驱动。不要把整套 agent 流程塞进 CLI，也不要把定时任务做成 skill 的章节。
7. **不做跨机器与隐式网络。** `.wiki/` 是单机事实源，不推拉、不合并账本；外部解析只是可选后端，不是运行前提。

## skill 原则

1. **技能写流程，不写用法。** 参数、字段、报错码以 `--help`、实际输出与 `SCHEMA.md` 为准；技能只写「什么时候做什么、做错了怎么判」。允许保留一份最小入口速查，因为 agent 需要先知道命令存在。
2. **按需分层。** `SKILL.md` 放入口、边界、最小序列与停点；`content.md` 写「写什么」；`ops.md` 写「出了问题怎么看」；`init.md` 只写首次接入的两件 agent 侧的事（持久化记忆、征得同意后建定时任务）。拆开是为了按需只读一份，不是为了增加契约。
3. **初始化对 agent 与人无感。** CLI 第一次运行自动建库；技能不提初始化流程，也不把 `E_NOT_INITIALISED` 当成需要用户决策的异常。`.wiki/` 已存在但契约或产品目录缺失时才由 `doctor` 诊断，这是损坏仓库的出口。
4. **停点只留给真正需要人的判断。** 结论冲突、删页、大改结构、无人值守时无法确认的取舍才停；机械步骤不逐条征求同意。
5. **汇报结论，不汇报内部形状。** 说清写到哪、哪些来源尚未确认、失败或 warning 是什么；不贴整份 JSON，不复述目录树。

## 改动的默认顺序

1. 先判断落在 CLI 还是 skill；两边都需要的，先改 CLI 与测试，再改技能话术。
2. 改命令、flag 或输出形状：同步 `tests/snapshots/cli-keys.json`、`tests/docs_contract.rs` 与相关文档。
3. 改文档：用会报错的编辑工具，并在同一轮 `grep` 到新内容；文档与代码同一个 commit。
4. 删命令或 flag 前，先回答「删掉以后坏了怎么办」，再 `grep` 一遍 `README.md`、`docs/readme/`、`docs/issues/`、`skills/` 与 `src/init.rs`。
