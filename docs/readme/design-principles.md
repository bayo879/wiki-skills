# 设计原则

## 交付物是技能，不是程序

`skills/llm-wiki/` 整个目录就是交付物：`SKILL.md` 给 agent 读，`scripts/wiki.py` 是引擎，
`references/` 是给人看的细节。复制目录即可使用，没有安装步骤、没有服务、没有全局状态。

这是 2026-11-13 转型后的唯一形态。Rust CLI、单二进制分发、`output/` 发布包都已停止维护，
源码归档在 tag `rust-archive-2026-11-13`。

## 引擎与 agent 分工

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| 引擎 | 扫描、解析、哈希、任务状态、载荷校验、引文核对、修订与渲染、镜像修复 | 判断哪份材料值得建页、写正文、选标题与边界 |
| agent | 读 raw 与已有页、决定来源归属、写正文与证据、提交载荷 | 直接改页面文件、手改数据库、跳过任务直接落盘 |

分工的边界由命令面固定：agent 能执行的只有 `init/ingest/next/submit/release/read/query/
page/export/status/doctor`。没有"直接写页"的入口。

## 账本是唯一事实源

页面正文、修订、证据、来源摘要、任务状态都在 `.wiki/wiki.db`。`.wiki/pages/*.md` 是按
账本渲染的**镜像**，用于人阅读、Git 查看与迁移，不是输入。

理由：如果页面文件是源，agent 顺手一改就会绕过引文校验与任务状态，且无法区分"人改的"与
"agent 改的"。把账本设为源后，镜像被改只会被覆盖并留证，写入必须走带校验的载荷。

镜像仍然保留（用户 2026-11-13 决定），因为它是免费的导出：离线浏览、diff、迁移都不需要
额外命令。`export` 只是把镜像按类型目录再复制一份。

## 任务状态机约束流程

来源被摄入后不是"agent 自己决定从哪开始"，而是引擎给出 route/page 任务：

- 一个来源一条 route 任务；route 通过后，每个目标页一条 page 任务。
- 任务有 `queued → leased → accepted`，领取带 15 分钟租约与递增 epoch。
- 提交必须带回 epoch；过期或已关闭的任务返回 `E_TASK_STALE`，不会写入。
- 校验失败零写入，任务退回队列并记录 `last_error`，修正后重新 `next`。

这样 agent 即使想跳过校验也没有接口；流程本身不是靠提示词约束，而是靠状态与校验。

## 不接管环境

技能不 OCR、不下载模型或语言包、不访问网络、不安装依赖。无文本层的文件标
`unsupported` 并给出提示，由人提供可复制文本。这条来自 2026-11-13 的一次事故：旧版技能
文档自相矛盾，agent 为补 OCR 自行下载语言包，被用户中止。

## 单机、单写者

SQLite 事务与文件原子替换保证单进程一致；任务租约只防止同一任务被重复领取，不解决库级
并发写。多 agent 的场景约定"一个写者 + 其他只读"。批处理默认 20 条，够用且便于中断续跑。

## 出参自解释

每条命令的 `--json` 输出带 `ok`、`cmd`、`version`、`root`、`summary`、`data`（或
`error{code,message,next}`）。错误码稳定，`next` 写下一步动作。agent 不需要读源码就能
判断如何继续。
