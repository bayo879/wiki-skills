# 开发方向详细决策

（本节由用户决策；agent 不擅自增删。）

- 移除候选暂存、`submit` 发布与工具内版本管理（含历史回退）。agent 不直接改 `.wiki/pages/`：它只提交页面载荷（title/summary/tags/status/正文），工具渲染 frontmatter、写 staging、在最后一个 page 任务关闭时整批合并。旧库遗留数据的处理方式另行确认，不自动删除。
- 保留尚未整理成知识页的来源待办，供中断后继续。来源由任务树结算：一棵根任务的所有 page 任务关闭后，根收尾合并页面、核对四道哈希并清除待办；资料变化则保留待办、根回到待路由。不发布页面、不生成版本、不自动追加来源。
- agent 不直接修改 wiki 结构是硬设定，但它是流程约束不是权限隔离：文件系统层面 agent 仍能写 `.wiki/pages/`，工具只能在任务关闭与根收尾时比对基线发现越界（`E_PAGE_CONFLICT`），真正的隔离靠运行时沙箱。
- 交互目标是「少交互、尽量无感」：能由规则直接判定的事就由工具自己处置，不要再让用户下一条命令。典型是源文件被删——raw、页面对它的引用、只靠它的孤儿页、账本行都应在下一轮摄入里自动收口，而不是等作者手工删页或跑额外命令。需要人判断的（正文冲突、结论取舍）仍然问。
- [未决问题](../issues/) 是整个项目的长期问题收集目录，后续优化以此为准，不限于摄入流程。一个未完成的设计或待判别的问题一个文件，写清影响、证据、候选方案与验收条件；未确认方案不得视为定案，解决后删除文件，断点留在 git 与提交信息里。每个文件头标 `优先级：P1`–`P4`：P1 正在丢数据，或流程卡死且没有出口；P2 用户会真实踩到，已有明确修法或只差一个决定；P3 低频路径的边界与设计缺口；P4 测试、评估与文档澄清，不改变当前行为。被问「issues 情况」时按优先级分组回答，P1 在前；该级没有条目就直接说没有，不硬凑。

- 确定性操作由 CLI 直接构造结果，不先要求 LLM 生成再校验：agent 只处理 CLI 无法确定的语义判断。页面来源、标识与路径、任务推进、索引维护和已知关系的正反向查询及固定格式拼接由程序负责；检索输出保留可继续遍历的链接与来源结构，支持多次检索完成多跳。关系是否成立等语义判断仍由 agent 提供。具体存储结构与接口尚待设计，不把 SQL 或 JSON 选型视为已定案。

- 摄入增加独立的「检索与归属」任务，每个来源一个任务；检索复用现有 `query`，检索现有 wiki 与决定信息归属在同一个任务中完成，信息提取也并入该任务，不另设独立提取任务，不仅靠提示词要求 agent 自觉推进流水线。归属不默认新建页面：先检索并判断已有页能否承载，有新增或修订则更新，已覆盖且无新增价值则不写页，仅在已有页不适合且值得独立成页时新建；归属完成前不创建写页任务，允许零写页结算。本次改动不考虑旧任务兼容与过渡，不新增旧任务保留区；这不授权自动删除现存数据。CLI 交付给 agent 的任务必须自解释：随任务提供处理说明、字段语义与填写责任、跨字段约束、有效示例及失败修正指引，不让 agent 靠字段名猜测；各任务交付入口共用契约，skill 不重复字段表。具体状态转换与载荷已在 `main ce69f3f` 实现并验收，见 `src/task/route.rs` 与 `src/task/contract.rs`。

- 所有交付给 agent 的命令出参都必须语义闭环，不限于任务：要么用自然语言直接说明信息，要么在消费前明确提供输出结构的释义与获取入口，不能只靠字段名猜。释义覆盖字段含义、引用作用域、空值/未请求/截断的区别、结果边界与后续动作；人类输出与 JSON 都不得省掉影响判断的信息，skill 不复制字段表。JSON 不裸交付：本次判断必需的事实、结果边界与后续动作用自然语言随结果说明；结构化材料保留精确信息，所需字段在消费前必须取得明确释义，不能把一段未覆盖全部所需字段的总结视为完整解释。自然语言说明与结构化数据必须表达同一份事实。检索列表是主体，固定字段释义外置到 CLI help，本次范围、缺失、未请求、截断及继续入口随结果提供；skill 必须说明结果含义、消费边界及何时先读取对应释义，不能只依赖 agent 自发查 help。“不复制字段表”不等于禁止说明结果的使用方式。具体字段形状、help 组织与版本策略另行确认。

- 在 `.wiki/` 内增加滚动运行日志，记录 CLI 处理过程供后续排查问题；日志独立于知识页、查询索引及旧 `journal.jsonl`，不是工具内历史或恢复机制。具体日志格式、保留策略与失败处理尚待设计确认。

- 对外分发以整个 `output/` 为根：CLI 放在 `.wiki/cli/`，两个技能放在 `.wiki/skills/`，安装引导放在 `.wiki/readme.md`。包内 CLI 从可执行文件位置定位根，不依赖调用目录；安装时以包内版本为准，替换旧 PATH 入口。分发空工具包不代表支持已有知识库跨机同步。
