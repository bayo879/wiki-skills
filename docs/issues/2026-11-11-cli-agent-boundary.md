# CLI 与 agent 的信息边界复盘

优先级：P2

## 问题

本次为静态审查，未修改 CLI 行为，未运行分发二进制的摄入流程，也未验证包内二进制与当前源码一致。以下实现结论以当前源码为准。

- 来源填写责任冲突：`output/.wiki/skills/llm-wiki/content.md:33-40` 仍要求作者填写 sources/updated，`output/.wiki/skills/llm-wiki-session/SKILL.md:46-55` 仍要求写 sources、保存 raw 哈希；实际 `src/task.rs:647-675` 自动保留原来源、追加当前 raw、生成日期。`src/init.rs:161-164` 对 updated 也同时写作者填写与工具填写。
- 数据库结构泄露为任务协议：`src/main.rs:549`、`src/main.rs:823` 直接返回 TaskRow；`src/store.rs:125-139` 包含 raw_hash、allowed_json、payload_json、attempts 与时间戳。agent 不参与这些字段的状态管理，payload_json 还是待再次解析的字符串。
- 当前任务与全量队列混在一起：`src/main.rs:537-586` 返回完整 pending、changes、固定说明及契约位置；`src/sync.rs:430-450` 的 affected_pages 是全部 work_items 的并集，不是当前根的范围，而 `src/task.rs:779-799` 按当前 raw 校验覆盖。`task done` 交付下一根时没有同等的 affected_pages 上下文（`src/main.rs:820-825`）。
- 完成判定缺少工具事实：技能 `output/.wiki/skills/llm-wiki/SKILL.md:44-45` 把 next_task 为空视为收敛；`src/task.rs:251-259` 对根收尾错误记失败后继续，最后可返回 None（314-316）。`src/main.rs:820-825` 只返回 closed/next_task/next_raw，未明确返回合并页面、失败根或未结来源。`src/task.rs:851-867` 又是先合并、后确认来源，因此“无下一任务”“叶关闭”“页面已合并”“来源已确认”不能混为一谈。
- 正常事件与可行动异常混用 warnings：`src/sync.rs:300-319` 将成功改名与改名碰撞都放入 warnings；技能 `output/.wiki/skills/llm-wiki/ops.md:6` 要求 Warn 给人看，容易把正常内部维护逐项转述。
- 程序性复验交给 agent：`output/.wiki/skills/llm-wiki/SKILL.md:40-45` 要求每轮先 doctor、完成后 query。`src/task.rs:855` 已刷新查询索引；索引是否包含已合并页面可以精确校验，不必靠自然语言 query 命中来证明。语义检索效果仍需 agent 判断。

## 影响

机械信息占用上下文、文档互相打架，agent 可能误填不由它拥有的字段；同时缺少真实合并与失败结算结果，可能把没有可执行任务误报为完成。当前根的判定材料不足，却暴露其他根的页面，增加漏判和错判风险。

## 候选方案

未定案：

- 明确任务交付是对 agent 的工作接口，不是数据库行导出；按任务种类只交付所需证据、目标、内容要求和可选动作。
- 来源引用的路径和日期继续由 CLI 注入；但某材料是否真正支撑结论、哪些旧证据已失效，仍是语义判断，不能把“当前来源触发了任务”当作充分证据。
- 对当前任务交付精确关联的 raw、目标页、brief 和 affected_pages；全树、哈希、重试计数、基线与完整变更清单按需诊断。
- CLI 显式提供已合并页、已确认来源、仍待处理/失败/阻塞项；不再由 next_task 是否为空推断完成。
- 区分正常维护事件、内容风险、需人决策的故障。默认汇报结果与风险；保留删除、部分生效、无法撤销等信息，不静默掩盖。
- 常规前置校验和索引一致性检查内化；doctor 保留独立深度诊断用途，query 保留内容查重、检索效果评价用途。
- 清理技能中来源/日期/哈希填写、staging 与结算机制的重复教程，保留行为边界和失败后下一步。

## 待确认与验收条件

- [ ] 明确默认 agent 输出与按需诊断输出的边界，不能丢失用户可感知的删除、部分成功与未完成信息。
- [ ] 来源注入责任在入口技能、内容技能、会话技能和生成契约中一致；确认是否需要表达旧引用失效。
- [ ] ingest 与 task done 交付同一种任务视图，每个根附带自身的受影响页集合。
- [ ] 收尾失败且 next_task 为空的用例明确报告未完成；已合并但来源确认失败的用例明确报告部分生效。
- [ ] 默认任务视图不含无需 agent 判定/回传的内部字段；诊断仍可追溯。
- [ ] 机械索引校验不依赖自然语言搜索命中；语义质量仍由 agent 负责。
- [ ] 实施时更新输出快照、契约测试与项目说明；用实际包内 CLI 验证分发行为。
