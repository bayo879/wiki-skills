# 摄入任务增加按来源的检索与归属阶段

优先级：P2

## 问题

当前源拆解在 `src/task.rs:744-776` 直接确定页面路径，`src/task.rs:802-821` 立即创建 page 子叶。`src/task.rs:454-473` 的 affected_pages 仅查引用当前 raw 的页面，不能找出其他来源支撑的同主题页。根收尾在 `src/task.rs:851-854` 按路径写入完整页面，不做语义去重或正文融合。

用户已确认：检索现有 wiki 与决定信息归属放在同一个独立任务，粒度为每个来源一个任务，检索复用现有 query；不能只靠提示词要求 agent 自觉依次执行。

## 影响

仅按源内容拆叶可能生成语义重复的新页；若不读旧正文就提交完整页面载荷，也可能覆盖旧知识。现有路径去重和哈希检查不能判断这些语义问题。

## 候选方案

未定案（任务粒度与独立阶段已确认，具体状态转换与载荷尚待设计批准）：已形成工作区 [spec 草稿](../superpowers/specs/2026-11-11-ingest-source-routing-design.md)，它是开发过程产物，不提交，不代表已实现行为。保留一个来源一棵根任务，源拆解先交付信息点，不确定页面路径；随后创建该来源唯一的检索与归属任务，使用 query 找候选并阅读相关页，将信息点分配到已有页、新页或无需写入，并说明依据；归属完成后按目标页归组创建写页子叶。写页任务负责融合旧正文与新证据，原有根收尾继续负责落盘与来源结算。

工具应拒绝跳过归属阶段直接创建写页任务；不新增独立搜索引擎。交付候选页与理由不等于证明真实调用了 query，是否需要调用证据关联尚未决定。

## 待确认与验收条件

- [x] 检索与归属为独立任务，不仅是提示词中的步骤。
- [x] 不考虑旧任务兼容或过渡，不新增旧任务保留区；不等于授权删除现存数据。
- [x] 每个来源一个检索与归属任务，复用 query。
- [ ] 确认最小设计与任务状态转换，归属完成前不开放写页子叶。
- [ ] 同一来源中归入同一目标页的信息点只生成一个写页任务。
- [ ] 所有信息点均有归属或不写理由；无须写页也有正常结算出口。
- [ ] 新来源能归入从未引用该来源的已有页。
- [ ] 明确结论冲突、检索不足与中断恢复的处理。
- [ ] 批准本版不做 query 调用证据追踪的范围；不能将自述检索视为实际调用证明。
- [ ] 更新技能中的旧写页表述，并同步行为文档与测试。
