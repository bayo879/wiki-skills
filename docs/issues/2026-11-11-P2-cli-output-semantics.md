# CLI 出参的语义闭环盘点

优先级：P2

## 问题

用户要求：所有流程中交给 agent 消费的出参，要么用自然语言直接表达信息，要么在消费前明确提供结构释义，不让 agent 靠字段名猜。这不限于 next_task。

本次为静态盘点：覆盖六条业务命令及其分支、公共信封/错误，以及 help/version 特例；核查源码、CLI help 定义、README、生成页面契约与技能。未运行摄入、未验证分发二进制，未修改产品行为。以下行号对应盘点时源码。

### 公共信封、错误与说明入口

- `src/report.rs:88-112` 的 emit_with 即使最终 exit 1，JSON 仍是 ok=true。例如 ingest 部分失败、doctor 出现 Fail；`src/main.rs:505-513`、`src/main.rs:259-263`。`README.md:123-137` 已说明信封和退出码，但没有解释 ok=true 不代表业务全部完成。不能只读 ok 或只读退出码就丢掉部分成功材料。
- `src/report.rs:126-146` 支持自然语言 message 与可选 detail，但 detail 无统一释义入口、每种错误的状态保留/已生效部分/安全下一步没有统一保证。需要逐错误分支验收，不能宣称所有错误都缺提示或都已闭环。
- `src/cli.rs:17-19` 只说明 JSON 格式；`src/init.rs:140-200` 生成的是页面契约，不是命令出参契约；`docs/readme/design-principles.md:24` 把字段解释交给 help/实际输出，但它们并未覆盖所有输出语义。Rust 注释和测试快照不等于 agent 已取得说明。
- `src/main.rs:1317-1325`：help/version 即使带 --json 也输出普通文本，这是“一条 JSON”声明的例外。应明确，不应强行为说明性入口制造任务协议。

### ingest：常规轮次、演练与解析预览

- `src/main.rs:532-581` 混合轮次汇总、全量待办、受影响页和当前任务；其中 affected_pages 是全部待办 raw 的引用页并集（`src/sync.rs:426-436`），不是当前任务专属范围，也不是语义检索结果。
- queued 是预算外等待转换的数量、waiting 是其键列表（`src/sync.rs:265-268`），pending 是已转换但尚未结算的来源；ingested 实际来自 work_items，并不代表已生成/合并知识页（`src/sync.rs:426-429`）。这些词不能只靠名字解释。
- `src/main.rs:586-613` 的人类输出没有 changes/stale_pages/ingested 的等价信息。哪些字段可以省略应以“是否影响决策”为准，而非要求逐字段照搬 JSON；删页、部分生效与失败不能被汇总数字遮蔽。
- 解析预览 `mode=full` 实际只返回前 200 字符的 markdown_head，而 chars 为全文字符数（`src/main.rs:31-32`、`src/main.rs:350-358`、`src/main.rs:1264-1301`）；不是全文。chunked 返回缓存目录，chunk/range 返回内容；需要交付模式、字符数口径、截断与如何取得完整内容的说明。
- 分块输入说明已有实质冲突：`src/cli.rs:65-68` 称 --range 为 INDEX/0=head，而 `src/main.rs:429-443` 实际接受 1-based 闭区间 A-B；`README.md:94` 同时组合互斥 chunk/range 且给出 0-4000。必须修示例，不是补一个字段表就能解决。
- 演练不交付任务的 next_task=None 不能被解释为全库已完成；分支含义应随输出说明（`src/sync.rs:270-291`）。

### task：done、status、retry

- 直接交付 TaskRow、缺少任务说明的问题已由来源归属任务（`main ce69f3f`）解决；本条不另造任务协议。
- `src/main.rs:816-834` 只返回 closed/next_task/next_raw；`src/task.rs:254-263` 收尾失败后标记失败并继续选任务。所以 closed、已写 staging、已合并页面、来源结算成功、全库完成是不同事实，next_task=None 只说明没有可交付任务，不能证明全部成功。更完整的交付边界见 [CLI 与 agent 信息边界复盘](2026-11-11-cli-agent-boundary.md)。
- `src/main.rs:837-884` 的 status/retry 人类输出是任务摘要，retry JSON 是 TaskRow。需说明 status 只观察、不推进；retry 是人工恢复入口且不意味着任务已执行或失败原因已消除，不能把重置结果当成交付/完成证明。

### query：文本、精确页面、精确来源、图

- 已有说明：`src/cli.rs:139-159` 解释关系方向、默认分页；`README.md:119,154` 解释 generation；生成页面契约说明 draft/stable/stale。不能说完全无契约。
- 来源字段作用域仍不完整：raw 是可能带片段的原始引用，raw_key 为规范化键，source 为 raw frontmatter 中原始源文件路径；source 缺省可能是 raw 缺失/不可读/字段缺失，不等于没有来源。raw_available 只证明 is_file，不证明可读、有效或支持结论（`src/query.rs:159-168,793-815,1043-1067`）。read 不解析 #片段，应交付可用读取方式，例如 raw:<raw_key>；query --source 忽略片段，反查的是整份 raw（`src/query.rs:686-703`、`src/read.rs:54-131`）。
- outgoing/incoming 是正文代码围栏外 wikilink 关系，sources/citing 来自 frontmatter sources，不是任意链接或语义关系（`src/relation.rs:123-167`、`src/query.rs:529-558`）。唯一裸 id、type/id 和完整页键的作用域与歧义出口应说明。
- 分页 total/next_offset/unresolved 的口径仅在实现中明确；unresolved 不计入已解析页 total。未请求关系被输出为默认空组，不能与真正无关系区分；sources 又不受 relation 选择限制（`src/query.rs:117-155,637-659,754-789`）。需要表达“未请求”，不能用释义替不可区分的数据辩解。
- 文本命中每方向关系先取 20 条（`src/query.rs:862-874`），人类输出隐藏截断、unresolved 与继续命令（`src/main.rs:1212-1251`）；count 只是本次返回数，不是总命中数，文本检索不使用 offset（`src/main.rs:987-1002`）。不能让 top-N 被当成全量。
- score 是相关性排序而非可信概率，snippet 不是全文；有链接或来源不证明结论成立（`src/query.rs:51-54,895-901`）。现有状态/作者核对说明只是部分兜底。
- 图的人类输出度数列无明确列名（`src/main.rs:1112-1118`），图字段和计数规则主要在 `src/graph.rs:38-68` 注释，需交付关系范围与计数口径。

### read

- 常规人类输出已给行区间、总行数与 next --offset，help 已解释 1-based 和 2000 行上限（`src/main.rs:666-675`、`src/cli.rs:76-93`），不必无差别添加长教程。
- JSON 缺窗口字段释义；空文件为 0/0，越界窗口 start=total+1/end=total、content 空，不是错误（`src/main.rs:645-664`、`src/read.rs:145-180`）。truncated 及续读应明确，不能把内容窗口视为全文。

### doctor

- 已以 name/level/detail 输出检查结果，detail 为自然语言，常规人类输出只显示非 Ok 项，是基本合理的自然语言路线（`src/doctor.rs:73-104`、`src/main.rs:271-295`）。无需为了统一结构给每条检查强加 schema。
- 仍需说明 Ok/Warn/Fail 的行为含义及结果边界：exit 0 可以有 Warn；--only 只是所选范围通过，不证明全库健康；--fix 修机械缺陷、不证明正文语义正确。修复结果可能与后续检查一同返回（`src/doctor.rs:153-189`）。逐条 detail 是否提供可行动出口仍应作为实施验收，不由本次静态审计一概背书。

### ignore：列表、增删、检查

- 列表及增删已经有简短自然语言结果（`src/main.rs:1142-1174`）；count 是当前规则数量，added/removed 是规则变化，不是已清理来源/页面的证明。
- 已发现实际错误：`src/ignore.rs:205-215` 明确 deciding_pattern 可返回 !反向规则，此时 ignored=false；但 `src/main.rs:1185-1189` 的人类输出只要 pattern 非空就说 is ignored。需按 ignored 表达结论，并解释 pattern 为最终决策规则、null 表示无规则匹配。不能只加结构释义而保留错误的人类结论。

## 影响

agent 可能将未请求当作不存在、将摘要/分页当作完整材料、将文件存在/搜索相关当作证据有效、将关闭叶子或没有下一任务当作来源全部结算。ignore 检查还存在自然语言与布尔结论直接相反的路径。字段快照只能锁形状，不能发现这些语义错误。

## 候选方案

已确认方向（2026-11-12）：

- JSON 不裸交付，不能仅凭键名认为 agent 已理解。结果可以自带判断必需信息，但必须用自然语言直接说明本次事实、结果边界与后续动作；不能只写“成功”或把状态枚举当成解释。
- JSON 保留精确的结构化材料。agent 需要使用的字段、引用、分页参数与状态值，必须在消费前取得明确释义；自然语言总结没有覆盖的字段，不能视为已经解释。固定释义允许通过明确入口提前取得，未取得前不得要求 agent 消费对应结构。
- 自然语言说明与结构化数据必须表达同一份事实，不能各自产生结论。检索列表是主体，不改写成综合答案；本次范围、未请求、缺失、截断与继续入口随结果提供，固定字段释义外置，不每次附完整字段教程。
- skill 必须直接说明结果的含义和消费边界：检索是候选材料，摘要不是全文，排序不是可信度；先确认范围、完整性与缺失提示，再沿页面、来源及关系引用核对或续查。首次使用某种输出模式或遇到不明确字段时，先读取 CLI 明确指向的对应释义，不凭键名猜测。
- help 提供精确字段释义，skill 提供稳定的消费规则与说明读取要求，当前输出提供本次事实和继续入口；不能只靠 agent 自发调用 help。关闭任务、页面合并、来源结算是不同事实，没有下一任务不代表全部完成。
- “skill 不复述字段表”不禁止说明结果的含义、使用边界与释义获取方式；不在 skill 重复维护完整字段表。以上为已确认分工，具体 help 组织、字段形状与版本策略仍待设计。

具体设计未定案：

- 简单结果直接自然语言表达；复杂结构提供可提前取得、被明确指向的统一出参释义。本次判断必需的事实和边界随结果用自然语言说明，不以外置释义替代。是否增加独立契约入口与版本标识尚待设计，不在此预设新命令或 JSON 库。
- 释义至少覆盖用途、字段/枚举/空值、引用类型及作用域、完整性与分页、成功与部分成功边界、安全下一步；任务交付另遵循来源归属 spec 的自解释要求。技能只保留说明获取入口和流程纪律，不重复字段表。
- 先修错误和不可区分状态，再补释义；不把数据库行注释直接贴出充数，也不把所有结果都改成冗长自然语言。
- 与现有边界问题分工：本条管理全命令出参语义清单与验收；来源归属问题管理新任务状态及载荷；CLI/agent 边界问题管理交付范围、确定性责任与真实结算事实。
