# 简单字体的 PDF 提取会把提示打到 stdout，破坏 `--json`

## 问题

`pdf-extract 0.7.12` 在简单字体缺少某个 code 的 `ToUnicode` 映射时使用 `println!` 输出提示（依赖源码 `pdf-extract-0.7.12/src/lib.rs:791`、`:841`）。本工具的 `--json` 输出直接写在标准输出，因此这些提示混在 JSON 之前，消费端按 JSON 解析会失败。

Type0 / Identity-H 路径不走该分支，只影响简单字体文档。

## 影响

- 自动化脚本与 agent 对含缺失映射简单字体的 PDF 执行 `llm-wiki --json ingest` 时可能解析失败，表现为 JSON 解码错误而不是一个明确的转换结果。
- 正文本身不丢失，属于输出协议问题，不是解析正确性问题。

## 候选方案

未定案。可选方向：

1. 在提取期间临时重定向/捕获标准输出，把提示转成 `warnings` 或丢弃（需要串行化，避免与并行转换互相干扰）。
2. patch/vendor `pdf-extract`，把 `println!` 改成日志或返回错误。
3. 在 `--json` 文档中声明该依赖行为，要求消费端容忍前缀文本（不推荐，契约不稳定）。

## 待确认与验收条件

- [ ] 确认 `--json` 是否承诺“标准输出只含 JSON”。
- [ ] 若修复：补一个简单字体缺失映射的样本，断言 `--json` 输出可被解析且转换结果完整。
- [ ] 确认修复不会在并行转换时把其他来源的提示混进本来源结果。
