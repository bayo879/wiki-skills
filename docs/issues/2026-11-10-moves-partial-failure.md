# moves 先改账本再改页，改页失败没有第二次机会

登记：2026-11-10　状态：未完成

## 问题

`src/moves.rs:260` 先提交账本改名（`Ledger::relocate_source`，同一事务删旧行、插新行、
迁移待办与缓存），`src/moves.rs:264` 才 `rewrite_pages(...)` 改页面里的 `sources`。

任何一页写失败：本轮 exit 1，旧键已不在账本里，下一轮 `moves` 无法再配对（新键被当作
新源），已改的页指向新 raw、未改的页指向旧 raw，两边都可能悬空。没有「待改写页」记录，
也没有重试入口。

## 影响

仓库改名是低频操作，但失败后修复要人工逐页找旧引用；`lint` 的断链检查能发现悬空，
却不知道该把它改回哪一边。

## 候选方案（未定案）

1. 先改页、后改账本：页失败则账本不动，可整轮重试；代价是页已改而账本失败时，
   页面引用一个新 key，同样要能重试。
2. 两步都做，但把「待改写页」写进账本/临时表，失败后下轮继续；需要新的状态位。
3. 页改写用「先写临时文件、全部成功后再 rename」的两阶段提交；跨多文件仍非原子，
   但失败面变小。

## 待确认

- 允许的中间态是「页新、账本旧」还是「页旧、账本新」；哪一个更容易被对账发现。
- 是否值得为低频操作引入新的持久状态。
